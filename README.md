# E-commerce ETL & Data-Quality Pipeline

An automated ETL pipeline in **Python, SQL (SQLite) and Linux shell** that takes four messy raw CSV files,
validates them with automated data-quality checks, cleans them, loads them into a relational database
with primary/foreign keys, and answers business questions with analytical SQL.

> **About the data:** the dataset is **synthetic**, generated by `generate_data.py` with a fixed seed.
> Realistic defects (duplicates, nulls, invalid values, orphaned foreign keys, inconsistent casing,
> mixed date formats) are injected on purpose so the pipeline has real problems to find and fix.

## Pipeline

```
generate_data.py        etl.py                                         run_queries.py
 raw CSVs (4)  ──►  extract ─► checks (before) ─► clean ─► checks (after) ─► load SQLite ──►  5 analytical
 with defects                                                (PK / FK / CHECK)               SQL queries
                                  └──────────────► data/quality_report.json
```

Orchestrated by `run_pipeline.sh` (timestamped logs in `logs/`) and by a GitHub Actions workflow on every push.

## Results (one run)

| Metric | Value |
|---|---|
| Raw rows in / clean rows loaded | 37,516 / 35,879 |
| Automated data-quality checks | 15 |
| Checks failing before cleaning | 15 |
| Defective rows found | 2,680 |
| Checks failing after cleaning | 0 |
| Foreign-key violations in the database | 0 |

Defects found include: 200 duplicate orders, 509 inconsistent order statuses, 499 missing unit prices,
249 each of orphaned order IDs, orphaned product IDs and non-positive quantities, 205 orphaned customer IDs,
205 deliveries dated before the order, 102 badly formatted city names, 84 non-ISO dates, and more.
Full breakdown: `data/quality_report.json`.

## Cleaning rules

| Problem | Fix |
|---|---|
| Duplicate keys | keep the first row |
| Inconsistent text (city, status) | trim whitespace, normalise case |
| Missing city / category | `Unknown` / `Uncategorized` |
| Invalid or missing product price | category median |
| Missing item unit price | look up the product price |
| Mixed date formats | convert to ISO `YYYY-MM-DD` |
| Delivery before order | set delivery date to NULL |
| Orphaned foreign keys, quantity <= 0 | drop the row |

## Analytical SQL (`queries.sql`)

Joins across all four tables, CTEs, and window functions: revenue by category, top 3 customers per city
(`RANK() OVER (PARTITION BY ...)`), monthly revenue with a running total (`SUM() OVER (ORDER BY ...)`),
average delivery days by city, and order status mix.

## Run it

```bash
git clone https://github.com/arjunpn03-spec/ecommerce-etl-pipeline.git
cd ecommerce-etl-pipeline
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
bash run_pipeline.sh
```

Schedule it daily at 02:00 with cron (`crontab -e`):

```
0 2 * * * cd /path/to/ecommerce-etl-pipeline && ./run_pipeline.sh
```

## Files

| File | Purpose |
|---|---|
| `generate_data.py` | builds the raw, deliberately messy CSVs |
| `etl.py` | extract, quality checks, clean, load, quality report |
| `schema.sql` | tables with primary keys, foreign keys, CHECK constraints, indexes |
| `queries.sql`, `run_queries.py` | analytical SQL and the runner |
| `run_pipeline.sh` | one-command, logged, fail-fast pipeline |
| `.github/workflows/pipeline.yml` | runs the pipeline in CI on every push |
